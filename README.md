## Описание проблемы

Цель работы - освоить базовые приёмы функционального программирования: функции, поток управления и данных, сопоставление с образцом, рекурсию, свёртку, отображение, функции как данные, списки. Для этого нужно решить две задачи Project Euler несколькими способами и сравнить их.

### Задача 3. Largest prime factor

Найти наибольший простой делитель числа 600851475143.

Ответ: **6857**. Число раскладывается как 71 · 839 · 1471 · 6857.

### Задача 18. Maximum path sum I

Дан треугольник из 15 строк. Идти нужно от вершины вниз, с каждой клетки можно перейти в одну из двух соседних клеток строкой ниже. Нужно найти максимальную сумму чисел вдоль пути.

Ответ: **1074**.

### Что требуется по методичке

Для каждой задачи сделано по шесть решений на Haskell:

1. хвостовая рекурсия;
2. обычная рекурсия;
3. модульная реализация (генерация, фильтрация, свёртка);
4. генерация последовательности через `map`;
5. списковые включения (в Haskell это замена циклам);
6. бесконечные ленивые списки.

И ещё по одной реализации на Java для сравнения.

## Ключевые элементы реализации

### Задача 3

Основная идея - пробное деление. Делим число на `d`, пока делится, потом берём следующее `d`. Когда `d * d > m`, то остаток - простое число, это и есть ответ. Хватает перебора до корня: у составного числа всегда есть делитель не больше корня.

**Хвостовая рекурсия.** Вся информация в аргументах `go`, вызов последний, стек не растёт.

```haskell
tailRec :: Integer -> Integer
tailRec x = go x 2
  where
    go m d
      | d * d > m = m
      | m `mod` d == 0 = go (m `div` d) d
      | otherwise = go m (d + 1)
```

**Обычная рекурсия.** Здесь `go` собирает список всех множителей, после вызова нужно ещё приписать `d` в начало, поэтому рекурсия не хвостовая.

```haskell
rec :: Integer -> Integer
rec x = maximum (go x 2)
  where
    go m d
      | d * d > m = [m]
      | m `mod` d == 0 = d : go (m `div` d) d
      | otherwise = go m (d + 1)
```

**Модульный вариант.** Три отдельные стадии: все делители, оставить простые, свернуть в максимум.

```haskell
modular :: Integer -> Integer
modular = foldl' max 1 . filter isPrime . divisors
```

**Через `map`.** Парные делители получаются отображением малых.

```haskell
mapped x = maximum (filter isPrime (ds ++ map (x `div`) ds))
  where
    ds = [d | d <- [1 .. isqrt x], x `mod` d == 0]
```

**Списковое включение.** Два вложенных "цикла" и условие.

```haskell
comprehension x =
  maximum [p | d <- [1 .. isqrt x], x `mod` d == 0, p <- [d, x `div` d], isPrime p]
```

**Бесконечный список.** Простые генерируются лениво, берётся ровно столько, сколько нужно.

```haskell
primes :: [Integer]
primes = 2 : filter isPrime [3, 5 ..]

infinite x = go x primes
  where
    go m ps@(p : rest)
      | p * p > m = m
      | m `mod` p == 0 = go (m `div` p) ps
      | otherwise = go m rest
    go m [] = m
```

### Задача 18

Два подхода. Первый - перебор всех путей (их 2^14 = 16384, для 15 строк это терпимо). Второй - динамическое программирование снизу вверх: в каждую клетку записывается её значение плюс лучшая из двух клеток под ней.

**Обычная рекурсия** (сверху вниз, перебор):

```haskell
rec = go 0 0
  where
    go r c
      | r == depth = triangle !! r !! c
      | otherwise = triangle !! r !! c + max (go (r + 1) c) (go (r + 1) (c + 1))
```

**Хвостовая рекурсия** (снизу вверх, аккумулятор - лучшие суммы нижней строки):

```haskell
tailRec = go (depth - 1) (last triangle)
  where
    go r acc
      | r < 0 = head acc
      | otherwise = go (r - 1) (zipWith3 (\x a b -> x + max a b) (triangle !! r) acc (tail acc))
```

**Через `map` и свёртку по строкам:**

```haskell
mapped = head (foldr1 step triangle)
  where
    step r acc = map (\(x, a, b) -> x + max a b) (zip3 r acc (tail acc))
```

**Модульный вариант.** Путь - список ходов (0 влево, 1 вправо), `paths` - бесконечный список поколений путей:

```haskell
paths = iterate (concatMap (\p -> [0 : p, 1 : p])) [[]]

value p = sum (zipWith (!!) triangle (scanl (+) 0 p))

modular = foldr (max . value) 0 (filter ((== depth) . length) (concat (take (depth + 1) paths)))
```

**Включение и бесконечный список:**

```haskell
comprehension = maximum [value p | p <- sequence (replicate depth [0, 1])]

infinite = maximum (map value (paths !! depth))
```

### Java для сравнения

Тот же алгоритм, но состояние меняется на месте.

```java
while (d * d <= n) {
    if (n % d == 0) n /= d;
    else d++;
}
```

```java
for (int r = t.length - 2; r >= 0; r--)
    for (int c = 0; c <= r; c++)
        t[r][c] += Math.max(t[r + 1][c], t[r + 1][c + 1]);
```

- `ghc -Wall` собирает код без предупреждений (сначала их было два: неявный `Double` в `isqrt` и неполный разбор списка в `infinite`, оба исправил);
- шесть вариантов каждой задачи запускаются вместе и должны дать одинаковый результат;
- ответы совпали с независимой проверкой на Python и с Java-версиями;
- настроен CI для GitLab (`.gitlab-ci.yml`) и GitHub (`.github/workflows/ci.yml`), он повторяет сборку и сверяет ответы.

Тестов на граничные случаи нет. Например, для `n = 1` варианты `mapped` и `comprehension` падают на пустом `maximum`, остальные возвращают 1.

## Выводы

**Хвостовая рекурсия** оказалась основным способом писать циклы. Состояние уходит в аргументы, стек не растёт. Читается чуть хуже, чем обычный `while`, зато нет изменяемых переменных, и ошибки "забыл обновить счётчик" невозможны.

**Обычная рекурсия** проще всего читается там, где задача сама рекурсивна (треугольник сверху вниз: значение плюс лучшее из двух продолжений). Но без запоминания она экспоненциальна: на 15 строк хватает, на 100 строк (задача 67) уже нет. Для таких случаев нужна версия снизу вверх.

**Свёртки, `filter` и `map`** позволили разбить решение на независимые стадии: что генерируем, что отбрасываем, как сводим. Такой код легко проверять по частям. Минус - промежуточные списки, из-за них модульные варианты задачи 3 заметно медленнее хвостовой рекурсии (перебирают все делители до 775 тысяч, вместо полутора тысяч шагов у `tailRec`).

**Списковые включения** оказались самым удобным способом записать вложенный перебор с условием. Читаются почти как математическая запись, при этом это обычный сахар над `map`, `filter` и `concatMap`.

**Бесконечные списки и ленивость** дали интересный эффект: можно описать "все простые числа" или "все поколения путей", не думая о границах, и брать только нужное. Но надо помнить, что ленивый список - это не итератор: он неизменяемый, вычисленные элементы запоминаются, по нему можно ходить повторно. Итератор (например, в Java или Python) одноразовый и изменяемый. Обратная сторона ленивости - трудно предсказать расход памяти, поэтому в аккумуляторах нужны строгие версии вроде `foldl'`.

**Сопоставление с образцом и сторожевые условия** (`go m ps@(p : rest)`, `| d * d > m = ...`) заменили цепочки `if` и обращения по индексу. Компилятор при этом проверяет полноту разбора, что и помогло найти пропущенный случай пустого списка.

**По сравнению с Java.** Java-код короче и быстрее: нет промежуточных структур, цикл работает на месте. Но алгоритм там слит в один цикл, а в Haskell его части можно разбирать, менять и переиспользовать отдельно. Для таких маленьких задач выигрыш Haskell не в скорости, а в ясности и в том, что типы и чистота отсекают целый класс ошибок.

Если подытожить, то правильный алгоритм (динамическое программирование для задачи 18, деление по ходу для задачи 3) важнее выбранного стиля. Остальные варианты полезны как упражнения на приёмы, а не как лучшие решения.
